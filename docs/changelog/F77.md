# F77 — Easier to use and easier to work on (0.77.0)

Makes the editor explain itself and check your work, gives scripts named functions with a reference, and reorganizes the editor and its runtime into smaller pieces.

## For people making games

- **Help everywhere in the inspector** (`componentHelp.ts`):
  - every component card says what the component is for;
  - fields that need explaining (Routine stops, instances, scatter, bodies, Animator graphs, routes, patrols, loadouts, masks) have tooltips.
- **Routine stops as a table**: hour, x, z and activity per row, with add and remove, instead of `"6 120 40 sit; ..."` text. The text stays the saved format.
- **Problems panel and checks before Play** (`contentCheck.ts`). The editor looks for mistakes the game would otherwise swallow:
  - a bad Routine stop, or a Routine with no stops;
  - a model id that isn't in the catalog, in a Renderable, ModelInstances or scatter rule;
  - Animator and SpaceSystem syntax errors;
  - follow, pursuit or patrol targets that match no entity's name;
  - empty scripts.

  Each problem names the entity, and clicking it selects that entity. Problems also show on the component's card. Play still starts; it warns, it doesn't block.
- **New offers templates** (`sceneTemplates.ts`): empty, third-person, first-person, racing and space starters, each playable at once.
- **Script API**:
  - Named helpers for what used to be string protocols: `space.set_hull(v)`, `space.plan(body)`, `audio.music(mood)`, `audio.ambience(layer, level)`, `hud.announce(text)`, `hud.waypoint(...)`, `fx.weather(rain, fog, wx, wz)`, `scanner.prospect(...)` and more.
  - The old `space.call` and `host.send` forms still work. Pale Signal's director now uses the helpers.
  - An **API reference** button on the Script card opens a searchable list of every callback, built-in and helper.
  - [SCRIPT_API.md](../SCRIPT_API.md) is the same list, and [scripting/engine_api.lua](../scripting/engine_api.lua) is a LuaLS stub for autocomplete in other editors.
- **[COMPONENTS.md](../COMPONENTS.md)**: every component and field with its default, generated from the editor's own tables.
- **[GETTING_STARTED.md](../GETTING_STARTED.md)**: a five-minute walkthrough from a template to a saved game.
- **Stats** says what limits the frame rate: nothing, the GPU, the simulation, or other CPU work.

## For people working on the engine

- **Named runtime fields**:
  - `editor_space_value` and `editor_value` fields have names: `SpaceField::reframe_yaw` in C++ and `SpaceField.reframeYaw` in TypeScript.
  - Both are generated from one table, `tools/bridge/fields.mjs`, instead of bare numbers.
- **A typed runtime boundary**: `tools/bridge/gen_exports.mjs` reads every `EXPORT` in the runtime and writes `runtimeExports.ts`. The editor's runtime type now comes from it, so a wrong function name or argument count fails to compile.
- **The runtime is split**:
  - `bridge_components.hpp` holds the gameplay components;
  - `bridge_runtime.hpp` holds BridgeHost and Runtime;
  - exports are in `bridge.cpp` (core), `bridge_combat.cpp` and `bridge_space.cpp`.
- **main.ts is smaller.** These parts moved into their own modules:
  - the inspector (`inspector.ts`);
  - the page layout (`editorLayout.ts`);
  - icons and DOM helpers (`dom.ts`);
  - UI painting (`uiDraw.ts`);
  - the Problems panel (`problemsPanel.ts`);
  - templates, the template picker, and the Script API panel.

  main.ts is down from 5,800 lines to about 5,300.
- **The docs are split**: this status page is now an index of `docs/changelog/F*.md`, one page per release.
- **Generated files are tested for being current**:
  - `bridgeGenerated.test.ts` covers the runtime fields and exports;
  - `scriptApi.test.ts` covers the Script API files;
  - `componentsDoc.test.ts` covers COMPONENTS.md.
- **Removed** a stray empty `test` file at the repository root.

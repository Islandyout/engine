# F97 — Action RPG widgets: skill bar, resource bar, status effects, target frame, damage direction, death screen, character sheet, quest log (0.94.0)

Where the UI kit was thin for an action RPG, and what was added ([UI_KIT.md](../UI_KIT.md)):

- **Gaps found** by comparing the kit with what action RPGs (Elden Ring, Sekiro, Ghost of Tsushima, Genshin, The Witcher 3) put on screen: no ability slots as a widget (the combat view drew its own, in one look whatever the style, labelled Q E R F whatever the bindings), no generic resource bar (scripts faked one with a text and a bar), no status effects, no target frame, no hit direction, no death screen or way back, no character sheet, no journal.
- **Eight widgets**, each in all six styles through the kit's own Paint toolkit (`uiKitRpg.ts`): Skill bar, Resource bar, Status effects, Target frame, Damage direction, Death screen, Character sheet, Quest log. Script-fed ones take their data from `ui.set_text` / `ui.set_value`.
- **Widget buttons**: `event:<name>` hits reach the script as `on_ui(<widget>, <name>)` (the death screen's respawn, the sheets' close).
- **The Player stays down** after dying until a script calls `melee.revive()`; it used to be destroyed four seconds after death, so there was nothing to bring back.
- **Skill slots follow the bindings** (`CombatView.setSlotKeys`), and the legacy slots stand down when a Skill bar is in the scene.
- **Azure Cloud Sect** now uses them: a Resource bar for qi, Status effects for meditating, flying and qi deviation, a Target frame, Damage direction, a Death screen with respawn, a Character sheet (C) and a Journal (J); the hand-made text and bar HUD is gone, and the menus have a dark backing in the Minimal style.
- Tests: uiKit unit tests (hidden when empty, buttons, bad lines), the murim browser test.

# F94 — Wiring UI without scripts, Objectives, worn gear (0.91.0)

The UI kit's menus, Settings, Inventory and Objective widgets could be placed but not wired except through hidden `on_ui` scripts. Now:

- **`UI.onClick`** ("When clicked"): one action per line, optionally `<event> ->` (`show`, `hide`, `toggle`, `give`, `take`, `equip`, `unequip`, `select`, `objective start|complete`, `text`, `script`, `pause`, `resume`, `restart`, `quit`, `settings`). Unknown actions are reported with their line. Buttons default to action `none` (a new element used to restart the game on click).
- **Screens that open with a key**: `UI.visibleWhen = "toggle"` plus `UI.toggleKey`; also `show/hide/toggle` actions and `ui.open/close/toggle` from Lua. Recipes: Screen: Inventory / Settings / Main menu.
- **Objectives** component (`id | title | detail | goal | on complete`): `collect`, `kill`, `reach`, `interact`, `script` goals tracked by the engine; chains and rewards; the Objective widget shows the running one; `objective.start/complete/progress` and `on_ui("objective", ...)`.
- **Worn gear has effects**: `Inventory.stats` (`Helmet: slot=head armor=30 damage=15 speed=-5 health=20`). Armor and damage apply in the single damage path (guns, melee, explosions, scripts), speed in the character controller, health as a maximum-health bonus.
- **Inventory widget** shows weight and kinds against the limits, the worn slots and each item; a click wears or takes off.
- Inspector: events an element sends, and **Add script hook** (writes an `on_ui` stub).
- C++: `Inventory.stats`, `editor_inventory_op` (the UI's access to `inventory.*`), the `editor.gear` health system. Tests: bridge (stats, armor, slot fit, health), `actionScript.test.ts`, `screens.cjs`.

Not saved between sessions: objective progress.

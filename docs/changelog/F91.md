# F91 — Inventory component and `inventory.*` (0.90.0)

Part 2 of the engine upgrade ([UPGRADE_DESIGN.md](../UPGRADE_DESIGN.md)).

- **`Inventory` component** (Gameplay > Loot group): `slots` (most kinds of item carried, 0 = no cap), `maxWeight` (0 = no cap), `weights` (`name=1.5, name=2`; unlisted items weigh 1) and `head` / `body` / `hands` (a carried item worn there). Guns and blades stay in slots 1-9 of `Weapons` / `Melee`; item counts stay with the entity's items.
- **Limits are enforced everywhere items arrive**: pickups, `inventory.add`, and the old `world.give_item`. A pickup that doesn't fit stays on the ground (part of a stack is taken, the rest stays) and the pickup feed says `Inventory full: <item>`. An entity without an `Inventory` carries without limits, as before.
- **`inventory.*` Lua API**: `add`, `remove`, `count`, `space`, `weight`, `list`, `slots`, `select`, `equip`, `unequip`, `equipped`. `world.items`, `world.give_item`, `world.take_item` keep working and are marked deprecated in the API docs.
- **Worn items follow the count**: removing the last of an equipped item takes it off.
- **Tests**: `editor_bridge_tests` (limits by kind and weight, partial adds, worn items, old names honour the limits, bad weights fail loudly).

Old scenes need no migration: without an `Inventory` nothing changes. Loadouts stay in `Weapons` / `Melee`; they are not copied into the new component.
